🎓 Project Documentation & Viva Guide

About ScamShield

An explainable, transparent AI/NLP-driven scam detection and cybersecurity awareness system engineered to combat digital social engineering and financial fraud.

🎯 The Problem & Our Mission

Digital deception has reached unprecedented levels through deceptive SMS, phishing emails, WhatsApp impersonations, and fake part-time job portals. Ordinary users are routinely manipulated into sharing OTPs or paying advance registration fees under high psychological pressure.

ScamShield's Solution: Rather than behaving like an opaque "black box" that simply labels text without explanation, ScamShield decomposes incoming communication into verifiable behavioral indicators (urgency, credential solicitation, shortened links, upfront payment demands) and provides an explainable 0–100 risk assessment with actionable defense steps.

⚙️ Technical Architecture & Pipeline

The system follows a modular 4-tier decoupled software architecture:

[User Input] → [Vanilla JS / HTML5 Client]
    ↓ REST (JSON)
[Flask Application API Router (app.py)]
    ↓
[ScamDetector Engine]
    └→ Text Normalization & Contextual Matcher (text_processor.py)
    └→ Deep Link & TLD Inspector (detect_links)
    └→ Category-Level Transparent Risk Scorer (risk_scorer.py)
    └→ Plain-Language Rationale Generator
    ↓
[Database Layer (firebase.py)] ↔ Firebase Firestore (with local fallback)
    ↓
[Interactive Results Dashboard (Circular SVG Gauge + Threat Cards)]
Frontend:

Semantic HTML5, CSS Grid/Flexbox, Vanilla JavaScript (No heavy frameworks).

Backend:

Python 3, Flask REST API, Modular Blueprints, Pytest automated testing.

Database:

Google Firebase Firestore with automatic offline JSON storage fallback.

Detection:

Explainable rule-based NLP, contextual phrase lookaround, URL shortener analysis.

🛡️ Public Cybersecurity Guidelines

1. OTP & 2FA Security

Never share one-time passwords with anyone, including individuals claiming to be bank executives, police, or courier agents.

2. Banking & CVV Protection

Do not enter your ATM PIN or CVV code to receive funds. UPI PIN is required ONLY to send money, never to receive money.

3. Link Inspection (HTTPS Fallacy)

HTTPS only guarantees that data is encrypted in transit?it does not verify whether the site owner is a legitimate organization or an attacker.

4. Upfront Job Fees

No legitimate company charges job applicants for security deposits, interviews, or laptop insurance fees.

5. Investment "Guarantees"

High returns with zero risk do not exist in genuine financial markets. Promises to double money within days are pyramid schemes.

6. Government & Police Impersonation

Law enforcement and tax departments do not conduct investigations or demand payment settlement over WhatsApp or Telegram calls.

🎓 College Viva & Placement Interview Q&A Guide

Review these frequently asked questions to confidently present ScamShield in front of internal/external examiners or technical recruiters:

Q1: Why did you choose an explainable rule-based system instead of a pure deep-learning model for Version 1?

Answer: In cybersecurity, trust and explainability are paramount. Pure deep-learning models (e.g. black-box neural networks) output a probability score but cannot explain why a message was flagged. Our system breaks down the attack into concrete vectors (such as shortened links, advance fee demands, or predatory OTP requests) and provides actionable defense recommendations. Additionally, rule-based heuristics have zero inference latency and work entirely on-premise without paid external APIs.

Q2: How does ScamShield prevent false positives on legitimate bank alerts that contain the word "OTP"?

Answer: We implemented contextual pattern analysis in TextProcessor. If a message contains benign advisory language like "NEVER share your OTP" or "Bank will never ask for your code", the system recognizes that the message is a safety alert and suppresses the predatory OTP indicator, correctly scoring the message at 0 (Low Risk).

Q3: Why doesn't repeat keyword spam artificially inflate the risk score?

Answer: In RiskScorer, we use category-level aggregation rather than raw keyword counting. Even if a message contains five different urgency keywords ("immediately", "urgent", "hurry"), the "Urgency" category is counted only once (+10 points), preventing artificial inflation and keeping scores bounded in 0–100.

Q4: What is the difference between "Risk Score" and "Probability of Fraud"?

Answer: A risk score measures the density and severity of suspicious behavioral indicators present in the text. ScamShield explicitly refrains from claiming 100% certainty that a message is fraudulent, because legitimate human messages may occasionally contain unusual phrasing. Our metric informs user vigilance rather than making legal determinations.

Q5: How does ScamShield analyze URLs? Does HTTPS guarantee safety?

Answer: The link inspector analyzes URL protocols, URL shorteners (bit.ly, tinyurl), high-risk TLDs (.xyz, .top), raw IP addresses, and excessive subdomains. Importantly, ScamShield teaches users that HTTPS only provides in-transit encryption between browser and server—it does NOT verify the honesty or legitimacy of the website owner.

Q6: How does the database layer integrate with Firebase Firestore?

Answer: We implemented a Repository pattern in firebase.py. If a Firebase service account credential file is provided in .env, it connects to Google Cloud Firestore. If credentials are not present, it seamlessly falls back to a resilient local JSON datastore, allowing the system to run out-of-the-box in any evaluation environment without crashing.

Q7: What privacy and security measures protect users when submitting reports?

Answer: We enforce strict input validation, length bounds (10 to 5,000 characters), anonymous masking by default, and automated client/server credential scrubbing to reject or warn against accidental submission of payment card CVVs or bank PINs.

⚠️ Limitations & Legal Disclaimer

ScamShield provides an automated risk assessment based on detected indicators and does not guarantee that a message is a scam or genuine. Sophisticated targeted spear-phishing messages that avoid obvious trigger words may receive lower scores. Always verify official requests directly with organizations through independent channels.
